Bootstrap Furniture Store

A detailed working paper for exploring Bootstrap through a static furniture store interface.

Project scope

The project is a single-page furniture store built with semantic HTML and Bootstrap 5.3.3. Bootstrap provides the responsive grid, spacing, typography, forms, tables and interface components. Its official JavaScript bundle powers the navbar collapse, dropdown, accordion, modal and offcanvas panel.

No PHP, database, custom stylesheet or custom JavaScript is required. The form demonstrates browser-side constraints and does not save a submission.

Open and inspect the project

Open bootstrap_furniture_store/index.html in a code editor and in a browser. The browser can open the file directly. If the project is served through XAMPP, copy the lab folder beneath the web root and use its local address. No database setup is involved.

Keep the browser developer tools open. Inspect an element to connect the visible page to its HTML classes, then resize the viewport to see responsive utilities change the layout.

Bootstrap setup and class pattern

At the top of index.html, the viewport declaration lets the page use the device width. The Bootstrap stylesheet follows it. Near the end of the document, the Bootstrap bundle enables components that respond to clicks.

<meta name="viewport" content="width=device-width, initial-scale=1">
<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
...
<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>

Bootstrap classes are combined in the HTML. For example, card establishes a component, shadow-sm adds a utility effect, and h-100 makes cards in a grid stretch to the same height. The component classes supply structure, while utilities tune spacing, color, display and alignment.

Navigation, collapse and dropdown

Find the first <nav> element. Its .navbar classes create the navigation component. .navbar-expand-lg keeps the links collapsed below the large breakpoint and expanded above it. The button's data-bs-target must match the id of the collapsible element.

<button class="navbar-toggler" type="button"
        data-bs-toggle="collapse" data-bs-target="#mainNavigation"
        aria-controls="mainNavigation" aria-expanded="false"
        aria-label="Toggle navigation">
    <span class="navbar-toggler-icon"></span>
</button>
<div class="collapse navbar-collapse" id="mainNavigation">
    ... navigation links ...
</div>

The dropdown uses the same relationship. A button has data-bs-toggle="dropdown", and the adjacent menu uses .dropdown-menu. The bundle listens for the click and changes the component state. No handwritten event handler is needed.

Try: change .navbar-expand-lg to .navbar-expand-md. Test at a width below and above the breakpoint, then restore the preferred behavior.

Containers, grid and gutters

The page content is wrapped in .container. A Bootstrap row groups columns, and each column defines how much space its content occupies. The product collection uses row column-count utilities, which apply the same column width to every direct child at a given breakpoint.

<div class="row row-cols-1 row-cols-sm-2 row-cols-lg-3 g-4">
    <div class="col">... product card ...</div>
    <div class="col">... product card ...</div>
    <div class="col">... product card ...</div>
</div>
ClassEffect in the project
.containerCenters content and applies responsive side padding
.rowCreates the grid row that contains columns
.row-cols-1Shows one collection card per row by default
.row-cols-sm-2Shows two cards per row from the small breakpoint
.row-cols-lg-3Shows three cards per row from the large breakpoint
.g-4Adds horizontal and vertical gutters between cards

Try: replace .row-cols-lg-3 with .row-cols-xl-4. Add a fourth card and compare the collection on medium, large and extra-large widths.

Spacing, flex utilities and typography

Bootstrap utilities handle common presentation adjustments directly in the class attribute. Their naming patterns are consistent. For example, mb-3 adds bottom margin, p-4 adds padding on every side, and text-secondary applies a theme color.

UtilityUse shown in the demo
py-4 py-lg-5Vertical padding grows at a larger breakpoint
d-flex flex-wrap gap-2Arranges action buttons and lets them wrap with consistent gaps
align-items-center justify-content-betweenAligns content on the cross axis and distributes it across a row
flex-grow-1 and mt-autoUses available card height to keep product actions aligned
display-5, lead, text-secondarySets a display heading, introductory paragraph and quieter supporting text

Try: vary the card descriptions. The product cards use .d-flex .flex-column on the body and .flex-grow-1 on description text so prices and buttons sit consistently.

Cards, badges, buttons and ratio placeholders

Each product is an <article> with Bootstrap's .card structure. The image area is a responsive .ratio container. Text inside the placeholder identifies the product without relying on external image files. A badge communicates a short status, and button variants distinguish the main action from a secondary one.

<article class="card h-100 shadow-sm">
    <div class="ratio ratio-4x3 bg-warning-subtle">
        <div class="d-flex align-items-center justify-content-center">
            Lounge chair
        </div>
    </div>
    <div class="card-body d-flex flex-column">
        <h3 class="h5 card-title">Marlow lounge chair</h3>
        <p class="card-text text-secondary flex-grow-1">...</p>
        <button class="btn btn-primary mt-auto" type="button">View details</button>
    </div>
</article>

Try: change a badge variant, use .btn-outline-primary for a secondary action, and add a fourth item. Keep the visual hierarchy consistent across all cards.

Forms and browser validation

Find the enquiry form. Every control has a visible label linked by matching for and id values. .form-control styles text inputs and the textarea. .form-select styles the select control. Grid columns place fields side by side on wider screens and stack them on narrow screens.

<div class="col-md-6">
    <label for="customerEmail" class="form-label">Email address</label>
    <input class="form-control" type="email" id="customerEmail"
           name="email" required>
</div>

The required, type="email", min and max attributes use native browser validation. Checkbox styling uses .form-check, .form-check-input and .form-check-label. The static project has no server, so the form does not save data.

Try: submit the form empty, then enter an invalid email. Add another field with a label and one of the Bootstrap control classes. Keep the label association valid.

Alerts, modal, offcanvas, accordion and collapse

The page includes several components whose appearance and behavior are provided by Bootstrap. Their triggers connect to a target through matching selectors and element IDs.

ComponentTrigger patternTarget in the project
Dismissible alertdata-bs-dismiss="alert"Closes the success message
Collapsedata-bs-toggle="collapse"#deliveryDetails
Accordiondata-bs-toggle="collapse"Care and assembly panels
Modaldata-bs-toggle="modal"#materialsModal and #productModal
Offcanvasdata-bs-toggle="offcanvas"#cartPanel
Dropdowndata-bs-toggle="dropdown"Navigation's More menu

Use buttons for actions. Match each target selector exactly, including the leading # in the trigger and the target id. Accessible labels such as aria-controls, aria-labelledby and aria-expanded describe component relationships and state.

Try: open and close each component using its trigger, its close button and, where applicable, the Escape key. Make sure opening one component does not leave an invisible overlay on the page.

Responsive tables, pagination and progress

The collection table is wrapped in .table-responsive, so a narrow viewport can scroll the table horizontally. The table uses a semantic header, row headings, striping and hover treatment. Text alignment utilities place prices consistently.

The pagination component groups page links and marks the current page. The progress component uses a labeled progressbar role and value attributes. These examples show Bootstrap styling and HTML semantics. Their values and links are static.

Try: add a product row with a heading cell, availability badge and price. Reduce the viewport width and verify the table remains reachable without forcing the entire page to overflow.

Implementation task

Personalize the furniture store while keeping it a single static HTML page. Make the collection show at least four products, apply a consistent color and button hierarchy, and adjust one responsive breakpoint. Add one extra form field with an associated label. Test every interactive component after editing.

Use Bootstrap classes for layout and component styling. Keep the HTML semantic, retain accessible names for controls, and do not add custom CSS or JavaScript.

Completion checklist

  • The page uses the Bootstrap 5.3.3 CSS and matching JavaScript bundle.
  • The navigation expands and collapses at its configured breakpoint.
  • The grid and product cards reflow without horizontal page overflow.
  • The product cards have consistent spacing and aligned actions.
  • The dropdown, dismissible alert, collapse, accordion, modal and offcanvas respond to their controls.
  • Form labels are associated with controls, and native constraints work.
  • The table remains usable on a narrow viewport.
  • No PHP, database, custom stylesheet or custom JavaScript was added.
